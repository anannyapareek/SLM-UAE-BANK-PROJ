As a transparent baseline we score each row with five hand-written rules, set from domain reasoning before looking at any results and not tuned. Each rule is a conjunction of thresholds on the same structured features the models use, read at the scoring time, so a rule only sees events up to that point in the session: R1 (off-hours session with a USB connect and file copies: off_hours == 1 and usb_connects > 0 and file_events > 0); R2 (leak, file-sharing or hacking site visited, with a USB connect in the same session: (http_filesharing_leak > 0 or http_hacking_tools > 0) and usb_connects > 0); R3 (job-search visits, with external email and attachments in the same session: http_job_search > 0 and external_recipients > 0 and attachments_count > 0); R4 (first logon by this user on this PC, outside working hours: new_pc == 1 and off_hours == 1); R5 (USB connects or file copies more than 3 standard deviations above the user's 30-day norm: (usb_connects_z > 3 or file_events_z > 3)). Every rule has weight 1, and a row's score is the sum of the weights of the rules that fire. Ties are broken by a planned tie-break that uses no labels: 0.01 times the percentile rank, within the split, of the row's total session events so far (unlocks_so_far, usb_connects, file_events, emails_sent, http_visits). The fired rule identifiers are kept as the explanation. Because the dataset records only file copies to removable media, R1 treats any file event as a USB copy. R3 approximates external email with attachments by requiring an external recipient and an attachment in the same session, as no feature links the two on a single email. R4 targets a published CERT threat pattern that does not occur in release r4.2 and is kept as a general rule. The rules carry prior knowledge: they were written by authors who knew the public CERT scenario descriptions, so the baseline is not blind to the threats it is scored on. The rules are deterministic, so we report a single run.
